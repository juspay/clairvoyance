# Jev (TypeSafe System One) as a judgment layer for Clairvoyance

**Status:** proposal. Nothing in this folder is wired into the runtime. It is the
read-through, the ranked list, one flagship design, the integration architecture,
and a reproducible multilingual evaluation, so that the first integration can be a
one-week PR instead of a research project.

## TL;DR

- **What Jev is.** A non-generative decision model behind one HTTP endpoint. You send
  a `state` (text or JSON) and a map of typed questions; it returns typed answers with
  calibrated probabilities: pick one of N (`choice`), position on 2 to 10 ordered
  levels (`score`), or P(yes) (`noul`). Server-side time is about 165 ms; input tokens
  cost about $0.04 per million and output is free. Many questions ride one request.
  It never writes text, cannot do arithmetic, counting or date comparison, and reads
  literally. Docs: https://docs.typesafe.ai.
- **Why it fits here.** Clairvoyance already makes dozens of "look at this text and
  judge X" decisions, made today by the main conversational LLM mid-call, by side
  LLMs that re-read the whole transcript every turn, by regex and keyword lists, or
  not at all. The CRM's own law, *an adapter classifies, it never decides*, is
  exactly the division of labour this model is built for.
- **Evidence.** On 155 authored items across English, Hinglish, Hindi, Tamil, Tanglish,
  Telugu, Tenglish, Kannada, Malayalam, Marathi, Gujarati and Bengali it scored 100%
  on reply classification, voicemail detection, call outcome and state lookup with
  zero flips across runs. On a noisy set the only misses were two-to-three-word
  romanised Kannada, Malayalam, Bengali, Gujarati and Marathi affirmatives, all at
  low confidence: a 0.9 confidence floor removes every error at 24 of 37 coverage, and
  a 0.7 floor leaves one error in thirty. See
  [04-evaluation.md](04-evaluation.md).
- **Where to start.** Three integrations, all off the voice turn path and measurable
  offline before they touch a customer: the live-call observers, post-call outcome
  verification, and WhatsApp reply classification in the CRM. See
  [01-use-cases.md](01-use-cases.md).
- **The best use case.** Turn every COD confirmation touch into a calibrated
  *ship-confidence* signal that a merchant's plan can branch on. See
  [02-flagship-ship-confidence.md](02-flagship-ship-confidence.md).
- **Hard limits.** Round trip from India is about 380 ms on a warm connection, so it
  does not belong on the per-turn voice path. Identity, reply attribution, the send
  gate, enrollment keys and split arms stay deterministic by law and are out of scope.

## Re-running the evaluation

```bash
TYPESAFE_API_KEY=... uv run python scripts/jev_eval.py base --models jev-latest,jev-preview --repeat 2
TYPESAFE_API_KEY=... uv run python scripts/jev_eval.py stress
```

The key is read from the environment and never written to disk.
